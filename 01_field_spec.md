# Field Spec — Schema + Resolution

One row per field: what it is, what it depends on, and what happens when a value is missing, ambiguous, or invalid.

| Field | Type | Allowed values / range | Parent / depends on | Required? | Default | If missing | If ambiguous / vague | If invalid / conflicting | Outcome |
|---|---|---|---|---|---|---|---|---|---|
| employment_type | enum | Full-time, Part-time, Contractor, Intern | None — anchor field | Yes — anchor | None | Ask directly — no default exists. | Unlisted term (e.g. "gig worker") → ask which of the 4 values it maps to, never guess. | — | ASK |
| country | enum | India, United States, United Kingdom | None — anchor field | Yes — anchor | None | Ask directly — no default exists. | "Global team" implies multiple → ask whether this is one policy or several. | — | ASK |
| minimum_tenure_months | integer (months) | 0 or greater | country (value); employment_type (override) | No — always auto-fills | India=3, US=0, UK=0; forced 0 if Intern | Never missing — auto-fills from country (overridden to 0 if Intern). | Intent stated with no number, and country default is non-zero (e.g. India=3) → auto-fill, but acknowledge the stated intent in assumptions text. | Intent stated with no number, but country default is 0 (US/UK) — 0 CONTRADICTS "want a waiting period" → do not auto-fill; ask directly for a number, stating the usual default conflicts with what they asked for. | AUTO / ASK-ON-CONFLICT |
| leave_type | enum | Annual, Sick, Unpaid (Contractor → Unpaid only) | employment_type (constrains allowed values) | Yes | None | Ask directly — no default exists. | Extracted with high confidence but employment_type not yet confirmed → treat as PROVISIONAL; do not ask about its dependents yet. | Annual or Sick requested while employment_type = Contractor → reject, don't ask. | ASK / REJECT |
| accrual_method | enum | Fixed days per year, Accrued monthly | leave_type (only applies if ≠ Unpaid) | Conditional — only if leave_type ≠ Unpaid | None | Ask — only if leave_type ≠ Unpaid. If leave_type = Unpaid, field doesn't exist (not just skipped). | — | — | ASK / N-A |
| accrual_amount | number (days) | 0 or greater | leave_type (only applies if ≠ Unpaid); pairs with accrual_method | Conditional — only if leave_type ≠ Unpaid | None — never guessed | Ask — only if leave_type ≠ Unpaid. Never guess a number. | Non-numeric answer (e.g. "a few days") → ask for the exact number. | Negative value → reject, can't be negative. | ASK / REJECT |
| carry_forward_allowed | boolean | true / false | leave_type (only applies if ≠ Unpaid) | No | false | Never blocks — defaults to false. | Vague rollover language with no explicit yes/no (e.g. "some flexibility to use leave later") → ask directly. A stated cap number (e.g. "up to 5 days") instead DIRECTLY implies true — resolve, don't ask. | Stated for leave_type = Unpaid → reject; not applicable, not just unlikely. | AUTO / ASK / REJECT |
| max_carry_forward_days | integer (days) | 0 or greater | carry_forward_allowed (only applies if = true) | Conditional — only if carry_forward_allowed = true | None — never guessed | Ask — only if carry_forward_allowed = true. Never guess a number. | Non-numeric answer (e.g. "some days") → ask for the exact number. | Negative value → reject. Stated for leave_type = Unpaid → reject. | ASK / REJECT |
| requires_approval | boolean | true / false | None — independent field | No | true | Never blocks — defaults to true. | — | Prompt contradicts default (e.g. "auto-approve everything") → confirm the override rather than silently accepting or rejecting it. | AUTO / CONFIRM |

**Legend:** ASK = open clarification question · REJECT = hard stop, status=rejected, no question asked · AUTO = silently resolved via default, optionally noted in assumptions · N-A = field removed entirely, not merely left blank.
